git remote add origin2 git@github.com:invocationofrights/whitepaper.git
git push origin2 master --tags
``` | Protect GitHub’s `main`/`master` with branch protection so Overleaf can’t accidentally force-push over edits. |
| **5** | **Future edits**: pull from Overleaf to local, commit, push to both remotes. Optionally set up a GitHub Action to sync one way nightly. | Merge conflicts are rare if you edit only in Overleaf *or* locally at any given time—never both in parallel. |

### 3 Repo architecture for the IoR organization

| Approach | Pros | Cons | Push-back |
|----------|------|------|-----------|
| **Monorepo** (website, whitepaper, script all in one) | Single issue tracker; easy cross-linking; Git subfolders handle docs vs. code | Bloated history; every website contributor clones LaTeX blobs; hard to grant fine-grained access | Could work now but will creak when translations & partner PRs flood in |
| **Split by function** *(recommended)* | • **invocation-script**: *canonical 4 lines*, language files, SemVer tags, CHANGELOG<br>• **whitepaper**: LaTeX + PDFs, releases tied to script tags<br>• **site-web**: Next.js source<br>• **site-static**: GH Pages artifact (keep as-is or migrate to branch deploy) | More moving pieces; need CI to keep versions in sync | Mirrors typical open-source pattern (think Kubernetes / docs / website). Gives you the clean, slim repo that partners can fork just for translations without pulling Next.js. |
| **Script as Git submodule** inside website repo | Keeps canonical text close to site; still isolatable | Submodules are notorious for tripping newcomers; Overleaf doesn’t support them | You’ll field endless “Why is my submodule detached?” issues. |

**My push-back:**  
- The four-line script *deserves its own repo* (`invocation-script`). That’s the artifact partners will fork, PR translations to, and tag (`v1.0`, `v1.1-draft`).  
- The whitepaper repo can declare a dependency in the header: “This draft references `invocation-script@v1.0`.” In CI you can fetch the script repo and embed the current text automatically to avoid drift.  
- Keep the Next.js code separate; web dev churn shouldn’t clutter legal history.
